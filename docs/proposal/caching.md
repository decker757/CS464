# §3.1 Caching strategy — draft

*Draft for the team. Every sentence is checked against the code listed below it; change the code and this changes.*

The system keeps almost no cache, on purpose, because most of what it serves is money or a price that moves money. Redis is a message bus, not a cache: the ledger PUBLISHes to two channels, `market.price` after a trade commits and `order.update` after a resting order fills, and the realtime service SUBSCRIBEs to both and relays them to WebSockets; Redis runs with persistence switched off, and no service ever reads a value back from it. Balances are never stored or cached: every read is `SUM(amount)` over the account's ledger entries, so the balance on screen equals the sum of the entries by construction (ADR 0009), and the ADR leaves a materialised snapshot for the day that aggregate is measured to be slow. The one precomputed read is the leaderboard. A background task on the ledger rebuilds the whole ranking every 60 seconds (`LEADERBOARD_REFRESH_SECONDS`) and stores it as a new generation, and a read serves the newest generation and marks it `stale` once it is older than two intervals (ADR 0021). Three smaller things behave like caches. The ledger copies a market's liquidity `b` and seed subsidy into its own book once, on first touch, and the copy cannot go stale because a published market's terms are frozen (ADR 0005). The ledger remembers a market_service `404` for 10 seconds per process, for at most 10,000 ids, so repeated requests for an unknown market are not forwarded each time. The realtime service keeps only a per-market `state_version` high-water mark to drop out-of-order frames. It does not keep the frames, so a reconnecting client fetches its snapshot from the ledger. No service and no proxy sets HTTP cache headers, and the frontend uses no query-cache library. Components keep what they fetched in React state and read it again on mount, and the browse page polls snapshots every 30 seconds only for markets the socket is not carrying. Not caching is a recorded decision. ADR 0017 refuses to cache a market's "open" status even for a few seconds, because the TTL would become a correctness parameter, and ADR 0022 refuses a cached suspension check for the same reason. ADR 0010 refuses to put a snapshot on the relay, because "a cache that cannot tell you it is empty is worse than no cache".
