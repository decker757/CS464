# §3.1 Caching strategy — draft

*Draft for the team. Every sentence is checked against the code listed below it; change the code and this changes.*

The system has no cache layer, by decision: what it serves is money or a price that moves money, and ADR 0017 and ADR 0022 refuse cached checks because the expiry would become a correctness parameter. The bus, managed Valkey in production and Redis locally, is pub/sub only: the ledger publishes `market.price` and `order.update`, the realtime service relays them, and nothing reads a value back. Balances are never stored or cached: each read is `SUM(amount)` over the account's ledger entries (ADR 0009). The one precomputed read is the leaderboard, a snapshot the ledger rebuilds every 60 seconds and marks `stale` past two intervals (ADR 0021). The ledger's copy of a market's `b` cannot go stale, because a published market is frozen, and a market_service 404 is remembered for 10 seconds. No API route sets HTTP cache headers; the production gateway caches the frontend's fingerprinted assets for a year and never `index.html`.
