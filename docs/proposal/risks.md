| 1 | **Nothing is deployed.** Continuous delivery is unbuilt. There is no staging or production environment, no public URL and no measured running cost. | High (certain) | High | A planned AWS design: ECS tasks behind an ALB, a separate RDS for staging and for production, and the migrate step as a gated one-off job. | 3 | **Database connection budget.** Each task holds a pool of 10 connections plus 10 overflow, and four services use the database. With 3 tasks per service and a rolling update that peaks at 4 (ECS rounds a 150% maximum down), that is 320 connections at peak, against roughly 450 for db.t4g.medium by AWS's formula, somewhat less in practice. A cap of 4 tasks per service would peak at 6 × 4 × 20 = 480 and exceed it, and requests would fail during a rollout. | Medium | High | The budget is worked out in diagram 02. The trade path releases its connection before each HTTP call (D-043). Set `max_overflow` explicitly, cap the task count, and add RDS Proxy or a larger instance if #20 calls for it. | Planned (design only). | Diagram 02's connection comment; `backend/*/core/database.py` |
| 4 | **The cookie needs one registrable domain.** The `SameSite=Lax` session cookie is not sent on cross-site requests. If the frontend and the API are on different domains, login fails silently, and so do live prices, because the cookie is the WebSocket's only credential. | Medium | High | Serve the frontend and the API under one registrable domain (`app.cs464.dev`) and set `COOKIE_DOMAIN` on auth. Move to `SameSite=None` only after adding CSRF tokens. | Planned in diagram 02. Today the setting accepts `none` with no CSRF defence. | ADR 0002 *Cookies for the browser, bearer tokens for services*; ADR 0010 *A relay that owns nothing, and a bus that is not the database* |
| 5 | **The migrate step could run once per replica.** It takes no lock. If two copies run at once, the loser exits 1 and its replica never starts. The pipeline can pass many times and then fail on the deploy where replicas happen to start together. | Medium | Medium | Compose runs one migrate step per schema and starts each app only after it exits 0. Tests fail if the scale override gives a migrate step more than one replica. #19 must run the step as its own job before rollout, or add an advisory lock. | Exists today in compose. Planned for the pipeline. | ADR 0020 *Migrations by Alembic, per service, run as a one-off step*; `docs/horizontal-scaling.md` |
| 6 | **Spot interruptions** in the planned design. realtime and audit run only on Spot, and the other services run on a mix of on-demand and Spot. A reclaimed task drops its in-flight requests and every socket on it. | Medium | Medium | The ALB drains the task. Each write is atomic, so one cut off rolls back. Trades and orders carry idempotency keys, so a retry is safe. The socket client reconnects with backoff and reads a fresh snapshot, and the browse page falls back to a 30-second poll. An interrupted settlement returns `503 settlement_unconfirmed`, and repeating the request finishes it. | Planned. | Diagram 02; ADR 0010; ADR 0019 *Settlement is the ledger's request, paid in one transaction, and market_service is told afterwards* |
| 7 | **A live access token cannot be revoked.** Logout, demotion and suspension each take up to 15 minutes to take effect, and market_service never learns of a suspension. | Medium | Medium | The access token lives 15 minutes. The ledger asks auth on every trade, so a suspended trader stops trading at once. Auth reads the live user row. A `jti` denylist is the named fix. | Accepted. | ADR 0002; ADR 0003 *A separate market service, and admin authority carried in the token*; ADR 0007 *A flat admin tier, and role changes audited rather than approved*; ADR 0022 |
| 8 | **Trading depends on three services.** Every trade calls auth and market_service, so if either is down, trading stops platform-wide. | Medium | Medium | Failing closed (`503`) is the right direction. Calls time out after 5 seconds, and each service would run as two or more replicas. | Accepted. | ADR 0017; ADR 0022 |
| 9 | **One Postgres is a single point of failure.** All four database services share one instance, and the planned RDS is in one AZ. | Low | High | Nothing is planned beyond RDS defaults. A managed instance with a standby is the named upgrade. | Accepted. | ADR 0001 *Self-host authentication instead of using a managed provider* ("The data tier is the real single point of failure"); diagram 02 |
| 10 | **The JWT secret is shared and HS256.** All five services hold `JWT_SECRET`, so any service that can verify a token can also mint one, including an admin's. | Low | High | Verifiers have no encode path, and a test fails if one is added. The secret goes in Secrets Manager. RS256 or EdDSA is the named upgrade. | Accepted. | ADR 0002; ADR 0003 |
| 11 | **Audit atomicity holds only while the services share one database.** An admin action and its audit entry commit together. A service moved to its own database would need an outbox and a relay. | Low | Medium | Every write goes through one function (`shared/audit.py`), and an outbox is the named upgrade. This rules out one RDS per service. | Accepted. | ADR 0006 *One shared audit log, written in the acting service's transaction* |
| 12 | **The append-only trigger on `ledger.entries` belongs to `ledger_svc`.** The role that writes the ledger owns the table and could drop the trigger. Changing the trigger needs a new Alembic revision. | Low | Medium | Superuser ownership, with INSERT and SELECT granted to the ledger, is the named upgrade. Tests assert that the entries sum to zero over the whole table and for each transaction. | Accepted (technical debt). | ADR 0009 *Double-entry with derived balances, and a lazily minted grant*; `backend/ledger_service/README.md` |
| 13 | **No rate limiting.** Nothing in `backend/` or `deploy/` limits request rates, so login is open to password guessing. | Medium | Medium | Passwords are hashed with Argon2id, which slows each guess. | 14 | **A gap between the commit and the price publish.** A crash or a Redis outage after a trade commits leaves screens showing an old price. Redis keeps nothing on disk. | Low | Low | A failed publish is logged and never fails the trade. Every frame carries a `state_version`. A client that reconnects reads a snapshot. The 30-second poll covers only markets the socket is not carrying, so a lost publish on a connected socket stays stale until the next frame. | Accepted. | ADR 0010 |

**Managing technical debt.** An ADR records each accepted risk with the condition that would reverse it. DECISIONS.md holds the smaller decisions, and code comments cite them by number. Guard tests pin the risky boundaries. For example, `test_the_audit_grant_is_exactly_insert` fails if the audit grant is widened, and the scale-override tests fail if a migrate step gains a replica. A risk above becomes work when its trigger fires, not before.
