# §4.3 Technical risks — draft

## Body version

The rows rated High for likelihood or impact, plus every risk #598 names: #19's deployment, #20's load test, HS256, the cookie rule and the connection budget. Only the last is not already High, so the body holds rows 1, 2, 5 and 7 to 11 of the full table, in its order and with its ratings. The full table, meant for an appendix, carries the rest, and the guideline's technical-debt bullet is the paragraph under it. L and I are likelihood and impact.

**Managing technical debt.** An ADR records each accepted risk with the condition that would reverse it. DECISIONS.md holds the smaller decisions, and code comments cite them by number. Guard tests pin the risky boundaries. For example, `test_the_audit_grant_is_exactly_insert` fails if the audit grant is widened, and the scale-override tests fail if a migrate step gains a replica. A risk above becomes work when its trigger fires, not before: row 2's very likely did on 2026-11-07, and until it is measured its next step stays written down as ADR 0031 rather than taken.
